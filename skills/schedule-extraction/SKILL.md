# 行程抽取

## 何时使用

- 用户点击“生成行程”
- Excel 没有独立日期列，日期写在备注、目的、备注2等任意字段
- 需要把“明天下午三点”“后天上午约了时间”“睡觉前”等表达变成行程
- 需要判断某条是否可以写入，还是必须问用户

## 规则

- 以生成当天为基准，时区 `Asia/Shanghai`
- 扫描所有文本字段，排除人员、联系方式、手机、电话、邮箱、微信、序号、ID
- 地址字段单独作为前缀，不重复放进活动内容
- 日期、时间必须在原文中找到；找不到就报 `needs_date`
- 没有具体时间 → 时段“需要配合”
- 上午/下午/晚上等模糊词 → 用对应时段，不编造钟点
- `3点`、`九点` 没有上午/下午 → `ambiguous_time`，暂停询问
- 同一行多个日期 → `conflict_date`，不自动选
- 精确时间写入单元格：`15:00 地址：事项`
- 同一格多条用换行；导出 Excel 用 `；` 连接
- 日期超出当前两周：自动扩展行程表，不丢弃

## 常用日期变体

- 周 / 星期 / 礼拜 视为同义
- 下个 / 下 / 下一个 / 下下个 / 这个 / 本 / 上个
- 下个礼拜四、下个星期四、下礼拜四、这礼拜四、下下个礼拜四
- 下个月三号、这个月18号

## 时间词表

- 上午：上午、早上、清晨、一早、早饭的时候
- 中午：中午、午饭、午休
- 下午：下午、下午茶、下班前
- 晚上：晚上、傍晚、夜里、晚饭、睡前、睡觉前、下班后
- 精确：下午3点、晚上九点、15:30、九点半
- 不确定：看时间、约了时间、具体看、具体时间、有空

## 输出

```json
{
  "baseDate": "2026-11-16",
  "items": [{
    "rowId": "r1",
    "person": "A君",
    "date": "2026-11-18",
    "slot": "上午",
    "time": "",
    "text": "打篮球 · 预备客户",
    "status": "ready",
    "writable": true,
    "evidence": [{"field": "note2", "label": "备注2", "raw": "后天上午约了时间，具体看"}]
  }],
  "issues": []
}
```

状态：`ready` / `needs_time` / `ambiguous_time` / `needs_date` / `conflict_date`。

## 实现

项目内实现：`app/services/schedule_extract.py`
接口：`POST /api/schedule/extract`、`POST /api/schedule/apply`
样例：同目录 `cases.json`

使用原则：规则优先；规则不认识时才调用模型；模型必须返回原文证据，找不到证据不采纳。
